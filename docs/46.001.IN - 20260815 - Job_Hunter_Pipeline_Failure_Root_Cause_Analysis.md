## 🔴 Root Cause 1: Flow3 Apply Crashed (Playwright Deadlock)

**Evidence:**
- `flow3.log` last entry: `2026-08-14 09:37:37` — *"Step 2: Launching Playwright browser to apply... [Applying - Thread] Senior Data Analyst (AI Compliance) at Binance"*
- The script deadlocked or crashed silently. Since it runs via `pythonw.exe` (silent scheduled task), the stack trace was swallowed.
- No Playwright/Chrome/Edge browser processes are currently running.
- The IPC daemon IS running (PID 22684), but its log shows repeated `Another instance already running (port 56200 in use)` errors.
- Last DB application records from Aug 14 22:14–22:29 show `retry_pending` and `skipped` statuses — no `applied` or `completed`.

**Mechanism:**
The `flow_apply.py` script has a 600s watchdog timeout. If Playwright hangs on a CAPTCHA, OTP challenge, or DOM change on the job board, the watchdog should kill abandoned browsers and mark the job as `failed_manual`. However, if the main thread itself deadlocked (e.g., the watchdog timer thread failed to fire, or the process was killed externally), the entire apply phase halts silently.

**Fix:**
1. Kill any orphaned Python processes: `python -m shared_platform.process_reaper`
2. Restart Flow3: `pwsh 10_ACTIVE_TIMEBOUND/Project/launchers/run_jobhunter.ps1 -Phase apply`
3. Check `flow3.log` for the crash context

## 🔴 Root Cause 2: Scrape & Score Pipelines Stalled

**Evidence:**
- `flow1.log` and `flow2.log` last updated: **2026-08-13** (2 days ago)
- `scrape_rotation_state.json` last updated: **2026-08-11** (4 days ago)
- Only 2 jobs were scored in the last 24 hours
- Scheduled tasks `Flow1_Scrape` and `Flow2_Score` exist and are marked `Ready`, but their triggers appear to not be firing correctly
- The most recent scrape activity was on Aug 14 at 18:38 (2 itviec/topcv jobs) — nothing on Aug 15

**Mechanism:**
The scheduled tasks use `wscript` silent invocation. If the underlying Python scripts crash on startup (e.g., import error, missing dependency, DB connection failure), they exit immediately without logging. The Windows Task Scheduler marks the task as "completed" successfully since `wscript` itself doesn't return the child's error code.

**Fix:**
1. Run scrape manually to see errors: `pwsh 10_ACTIVE_TIMEBOUND/Project/launchers/run_jobhunter.ps1 -Phase scrape`
2. Run score manually: `pwsh 10_ACTIVE_TIMEBOUND/Project/launchers/run_jobhunter.ps1 -Phase score`
3. Check Windows Task Scheduler → Task History for `Flow1_Scrape` / `Flow2_Score` exit codes
